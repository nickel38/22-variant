# Эмулятор оболочки — практическая работа №1, вариант 22

Проект выполнен по заданию из сборника практических работ по дисциплине
«Конфигурационное управление». Это консольный эмулятор UNIX-подобной
оболочки с виртуальной файловой системой (VFS). Все изменения VFS выполняются
в оперативной памяти; исходный XML-файл не распаковывается и не изменяется.

## Требования и запуск

Нужен Python 3.10 или новее. Внешние пакеты не требуются.

```sh
./run.sh
./run.sh --vfs examples/vfs/files.xml
./run.sh --vfs examples/vfs/files.xml --startup scripts/stage4_success.txt
```

Параметры командной строки:

| Параметр | Назначение |
| --- | --- |
| `--vfs PATH` | XML-образ виртуальной файловой системы |
| `--startup PATH` | Стартовый скрипт, одна команда на строку |
| `--help` | Справка argparse |

При запуске приложение печатает все параметры в формате `ключ=значение`.
Команда `conf-dump` повторяет этот вывод внутри эмулятора. Стартовый скрипт
показывает каждую строку как ввод с prompt и останавливается при первой ошибке.

## Команды

Prompt содержит имя пользователя и hostname реальной ОС. Поддерживаются
кавычки и раскрытие `$NAME` и `${NAME}` из окружения процесса.

| Команда | Возможности |
| --- | --- |
| `ls [ -l ] [PATH...]` | список узлов VFS или подробный список владельцев |
| `cd [PATH]` | переход по каталогам VFS; `cd` без аргументов возвращает в `/` |
| `uptime` | время работы текущего эмулятора |
| `who` | текущий пользователь и время запуска сессии |
| `chown [-R] OWNER[:GROUP] PATH` | изменение владельца в памяти, `-R` — рекурсивно |
| `conf-dump` | параметры запуска в формате ключ-значение |
| `exit` | завершение сессии |

Ошибки неизвестных команд, аргументов, путей и VFS выводятся с понятным
сообщением. Ошибка стартового скрипта возвращает ненулевой код завершения.

## Формат XML VFS

Корневой элемент имеет вид `<vfs name="...">`. Элементы `directory` и `file`
используют абсолютный атрибут `path`. Содержимое файла хранится в base64;
владелец и группа задаются необязательными атрибутами `owner` и `group`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs name="demo">
  <directory path="/docs" owner="student" group="students" />
  <file path="/docs/readme.txt">SGVsbG8hCg==</file>
</vfs>
```

Загрузчик отклоняет отсутствующий или повреждённый XML, неверный корневой
элемент, небезопасные пути, дубликаты, конфликт файла с каталогом и неверный
base64. Родительские каталоги создаются только в памяти.

## Проверка

```sh
python3 -m unittest discover -s tests -v
./scripts/stage1_demo.sh
./scripts/stage2_demo.sh
./scripts/stage2_error_demo.sh
./scripts/stage3_demo.sh
./scripts/stage3_errors.sh
./scripts/stage4_demo.sh
./scripts/stage5_demo.sh
```

Сценарии `stage3_demo.sh` используют минимальный, многофайловый и трёхуровневый
XML-образы. Сценарии с суффиксом `errors` или `error` специально проверяют
ненулевой результат и остановку после первой ошибки.

## Структура и история этапов

Исходный код находится в `src`, тесты — в `tests`, примеры VFS — в
`examples/vfs`, демонстрационные сценарии — в `scripts`. Скрипт `run.sh`
работает из любого текущего каталога.

Этапы сохранены отдельными Conventional Commits:

1. `feat(stage-1): add shell REPL prototype`
2. `feat(stage-2): add startup configuration and scripts`
3. `feat(stage-3): load XML virtual filesystems in memory`
4. `feat(stage-4): implement filesystem and system commands`
5. `feat(stage-5): add in-memory chown command`
